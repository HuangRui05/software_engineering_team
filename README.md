# MUD 文字冒险游戏
本项目是一款基于前后端分离架构的文字地牢冒险游戏，支持玩家登录、房间查看、方向移动、指令交互等功能。项目遵循软件工程规范，包含接口契约、自动化测试、持续集成、模块化设计，适合团队协作开发。

----------------------------------------
# 一、系统架构图（模块关系）
本项目采用三层模块化架构，模块之间低耦合、高内聚：

1. 接口契约层
   - docs/openapi.yaml：全局接口规范文件，定义所有请求/响应格式
   - 提供 Mock 服务支持，实现前后端并行开发

2. 业务逻辑层
   - 玩家模块：登录、状态管理、身份校验
   - 房间模块：房间数据、描述、出口管理
   - 指令解析模块：处理 look、go 等用户指令
   - 移动模块：判断方向是否合法，切换玩家位置

3. 展示交互层
   - 前端交互界面
   - 接收用户输入，调用接口，渲染游戏信息

----------------------------------------
# 二、本地开发环境搭建步骤
新人按照以下步骤，可快速搭建完整运行环境：

1. 克隆代码到本地
git clone 项目仓库地址
cd 项目目录

2. 安装依赖
npm install

3. 启动 Mock 服务（用于前端开发）
prism mock docs/openapi.yaml

4. 启动游戏服务
python my-mud-game/app.py

5. 访问游戏
打开浏览器访问：http://localhost:5000

6. 运行单元测试
pytest tests/ -v

----------------------------------------
# 三、核心业务模块职责说明
每个模块职责清晰，便于维护与扩展。

1. 玩家模块（player）
   - 功能：玩家登录校验、玩家状态保存、身份验证
   - 输入：用户名、密码
   - 输出：登录成功/失败、玩家当前状态

2. 房间模块（room）
   - 功能：管理所有房间信息
   - 包含：房间名称、房间描述、房间出口
   - 提供查询当前房间、切换房间功能

3. 指令解析模块（command）
   - 功能：解析用户输入的指令
   - 支持指令：look、go、login、exit
   - 将指令分发给对应模块

4. 移动模块（move）
   - 功能：判断方向是否合法
   - 检查当前房间是否允许往该方向移动
   - 移动成功后更新玩家位置

5. 接口契约模块（openapi）
   - 功能：统一前后端接口规范
   - 提供 Mock 服务
   - 确保前后端字段一致、不冲突

----------------------------------------
# 四、项目工程化规范
1. 使用 Git Flow 分支管理：所有功能在 feature 分支开发，通过 PR 合并到 develop
2. 使用 OpenAPI 3.0 规范接口
3. 使用 pytest 进行单元测试，所有测试纳入 CI 自动执行
4. 使用 GitHub Actions 实现持续集成，保证代码质量
5. 前后端通过 Mock 服务解耦，可独立开发

----------------------------------------
# 五、如何贡献代码
1. 从 develop 分支创建新功能分支
2. 完成开发并编写单元测试
3. 提交 PR，等待自动测试通过
4. 代码合并后自动触发 CI 测试
